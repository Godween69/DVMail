# Админка почтовых ящиков (apps/admin)

Маленькое приложение для владельца сервера: создать ящик, сбросить пароль ящика и удалить ящик
в Stalwart. Письма оно не читает. Наружу не публикуется.

## Как это работает

Админка обращается к Stalwart по JMAP с API-ключом служебного аккаунта (роль Administrator).
Список методов ограничен: только домены и аккаунты. Ящик создаётся с ролью User и случайным
паролем из 32 символов. Пароль показывается один раз и нигде не хранится. После создания
админка пробует войти под новым ящиком и сообщает результат.

Сброс пароля: кнопка «Сбросить пароль» у ящика задаёт новый случайный пароль (32 символа),
показывает его один раз с кнопкой копирования и так же проверяет пробным входом. Сбрасывать
можно сколько угодно раз. Пароли ящиков нигде не хранятся: если пароль потерян, его сбрасывают.
Меняется только поле secret основного пароля, точечной правкой credentials/ключ/secret.
Пароли приложений и двухфакторка не затрагиваются: Stalwart отдаёт секреты скрытыми, поэтому
заменять весь список учётных данных нельзя, он потерял бы пароли приложений.

## Защита

- Вход по отдельному паролю админки. Хранится только хеш (scrypt).
- Сессия: токен в cookie (HttpOnly, SameSite=Strict), на сервере хранится его хеш.
  Простой 15 минут или 4 часа в сумме завершают сессию.
- Лимит неудачных входов: 5 с одного адреса и 15 всего за 15 минут.
- Проверка заголовка Host (защита от DNS rebinding) и защита от подделки запросов:
  свой заголовок, проверка Origin и Sec-Fetch-Site.
- Строгая политика страницы (CSP): только свои скрипты и стили, без встроенного кода.
  Страница на чистом JS без innerHTML.
- Защищённые ящики (по умолчанию hello) и любые ящики с ролью выше User не удаляются.
  Удаление только с вводом имени ящика, сброс пароля только после явного подтверждения.
  Зарезервированные имена создать нельзя. У защищённых ящиков нет ни удаления, ни сброса.

## Установка

Как собрать образ, подготовить секреты и безопасно открыть админку по SSH с переадресацией порта:
docs/DEPLOY.md, раздел про админку.

## Настройка

Секреты читаются из файлов, в переменные окружения и журналы они не попадают.

- STALWART_URL: адрес Stalwart (по умолчанию http://dvmail-stalwart:8080)
- STALWART_TOKEN_FILE: файл с API-ключом (по умолчанию /run/secrets/stalwart_token)
- ADMIN_PASSWORD_HASH_FILE: файл с хешем пароля (по умолчанию /run/secrets/admin_password_hash)
- ALLOWED_DOMAIN: домен ящиков
- PROTECTED_NAMES: защищённые ящики через запятую
- HOST и PORT: адрес и порт (по умолчанию 127.0.0.1:3100)
- ADMIN_HOSTS: допустимые значения заголовка Host

Хеш пароля делает apps/admin/tools/make-password-hash.mjs (скрытый ввод, минимум 12 символов).

## Тесты и образ

    npm test --workspace @dvmail/admin
    docker build -f apps/admin/Dockerfile -t dvmail-admin .

Тесты работают на заглушке Stalwart; правка пароля дополнительно проверена на настоящем
Stalwart 0.16 на временном ящике (создан и удалён). Образ собирается в несколько ступеней, в итоговый
образ не попадают инструменты сборки, процесс идёт без root.

## Ограничения

- Сохранность паролей приложений при сбросе опирается на семантику точечной правки: проверить её
  через API админки нельзя, Stalwart разрешает создавать пароли приложений только самому
  пользователю.
- Ключ служебного аккаунта даёт полный доступ к ящикам. Файл с ним должен быть доступен
  только администратору и контейнеру.
