# Второй фактор для входа в веб-почту (DV Auth)

Необязательная возможность. Без неё DVMail работает как раньше: адрес и пароль приложения.
Подключается отдельной службой DV Auth (https://github.com/Godween69/DVAuth), той же, что может
защищать другие ваши сайты, например облако DV Cloud. Своих приложений для почты не нужно:
всё происходит в браузере, а подтверждение приходит в приложение DVChat.

## Как это выглядит для человека

1. Человек вводит адрес и пароль. Сервер проверяет их в Stalwart.
2. Если у ящика включён второй фактор, сайт показывает экран «Подтвердите вход»: QR-код и число.
3. В DVChat человек сканирует QR (или открывает ссылку на телефоне), сверяет адрес и браузер
   и вводит число. Страница сама узнаёт о подтверждении (опрос раз в 2 секунды) и открывает почту.
4. Запасные пути: код из приложения-аутентификатора (Google Authenticator, Aegis, 2FA и т. п.)
   или одноразовый запасной код. Ссылка «Ввести код вручную».

Включается каждым ящиком отдельно: кнопка «Безопасность» (щит) в левой колонке. Там привязка
DVChat, коды из приложения и выпуск запасных кодов. Каждое изменение требует пароль приложения
и действующий второй фактор.

## Как подключить

Задайте две переменные контейнеру dvmail-web (обе или ни одной):

- DVMAIL_AUTH_URL: внутренний адрес DV Auth, например http://dvauth:3011 (схема, хост, порт, без пути).
- DVMAIL_AUTH_SECRET: секрет этого приложения из DVAUTH_CLIENTS в настройках DV Auth, не короче 32 знаков.

DV Auth должен быть доступен из контейнера dvmail-web по внутренней сети. Наружу порт DV Auth
открывать не нужно. Секрет не кладите в compose-файл: используйте env_file с правами 600.

## Что гарантируется

- Закрытый вход: если DV Auth настроен, но не отвечает, не принимает секрет или отвечает
  перенаправлением, вход закрыт (сообщение «Сервис второго фактора сейчас недоступен»).
  «Не знаю, включён ли второй фактор» не считается «не включён». Уже открытые сессии не
  затрагиваются.
- Сессия открывается только после второго шага. До него пароль и талон DV Auth хранятся
  только на сервере, в памяти, зашифрованными ключом из короткой куки `__Host-dvmail_pend`
  (5 минут). Браузер талона не видит.
- Человека DV Auth узнаёт по постоянному номеру ящика в Stalwart (accountId), а не по адресу.
  Если DV Auth вернул другого человека, вход отклоняется.
- В DV Auth передаётся настоящий адрес клиента: по нему считается блокировка перебора.
  Неверный пароль до DV Auth не доходит.
- Ошибки настроек (неверный пароль, неверный код) возвращаются как 403, чтобы не сбросить
  открытую сессию. Перебор ограничен общим счётчиком попыток входа (429).

## Аварийный выход

Если DV Auth сломался и нужно срочно войти: удалите обе переменные DVMAIL_AUTH_* и перезапустите
dvmail-web. Вход вернётся к паролю приложения. Верните переменные, когда DV Auth заработает.
Для человека, потерявшего телефон и запасные коды, второй фактор сбрасывает владелец через
DV Auth (запрос /v1/reset, см. docs/API.md в репозитории DV Auth).

## Проверка

`npm test` в корне прогоняет заглушки Stalwart и DV Auth (apps/server/test/twofactor.test.mjs):
вход без второго фактора, с кодом, с чатом, чужой человек, просроченный талон, недоступный
DV Auth, настройки и ограничитель попыток.
