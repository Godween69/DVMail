# Структура проекта

Проект собран как набор пакетов в одном репозитории (npm workspaces).

## Папки

- packages/crypto: расшифровка писем S/MIME (AES-256-GCM, RSA-OAEP). Работает в браузере и в Node. Единственная зависимость: asn1js. Тесты создают одноразовые ключи через openssl, ключей в репозитории нет.
- apps/server: сервер на NestJS. Хранит сессию, ходит к почтовому серверу по JMAP, отдаёт собранный сайт, письма не расшифровывает и закрытых ключей не видит. Слушает 127.0.0.1:3000. Образ Docker: apps/server/Dockerfile (сервер и сайт вместе). Подробности в docs/WEB.md.
- apps/web: страница на React и Vite (анимации Motion, очистка писем DOMPurify). Расшифровка писем будет происходить здесь, в браузере.
- apps/admin: локальная админка почтовых ящиков (NestJS и простая страница без сборки и без чужих библиотек). Отдельный образ Docker (apps/admin/Dockerfile), в webmail не входит. Подробности в docs/ADMIN.md.

## Команды (из корня репозитория)

- npm install: установить зависимости всех пакетов
- npm test: тесты расшифровки, входа и отправки в webmail, логики письма на странице и админки
- npm run build: собрать сервер, админку и страницу
- npm run licenses: проверить лицензии зависимостей

## Правила

- Лицензии зависимостей: MIT, BSD, Apache-2.0, MPL-2.0. Лицензии ISC и 0BSD по сути равны MIT и допускаются, но каждая такая зависимость видна в отчёте. AGPL и GPL в приложение не попадают.
- Закрытые ключи, пароли и токены не хранятся в репозитории (см. .gitignore).

## Заметки

- В корневом package.json стоит overrides для multer 2.5.0: у версии 2.4.0, которую тянет NestJS, есть уязвимость отказа в обслуживании (GHSA-q7qp-rjg7-q26m). Когда NestJS обновит зависимость, override можно убрать (проверять через npm audit).
