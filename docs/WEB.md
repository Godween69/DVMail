# Веб-клиент (apps/server и apps/web)

Читалка писем для ящика на Stalwart. Один контейнер: сервер NestJS отдаёт собранный сайт
React и работает посредником между браузером и Stalwart по JMAP. Письма на диске сервер
не хранит. Пароль живёт только в памяти процесса, зашифрованным.

## Что умеет сейчас (этапы А, Б1 и Б3)

- Вход по адресу и паролю. Если у ящика включена двухфакторка, входить нужно паролем
  приложения (создаётся в личном кабинете Stalwart). Одиночный основной пароль у такого
  ящика не работает: Stalwart требует одноразовый код.
- Папки (названия по ролям: Входящие, Черновики, Отправленные, Спам, Корзина), счётчики
  непрочитанных, список с подгрузкой, поиск по письмам.
- Чтение письма: текст и оформленный вид. Пометка «прочитано» при открытии, «не прочитано»
  вручную, удаление (в корзину; из корзины насовсем, с подтверждением).
- Вложения только скачиванием, письмо целиком скачивается как .eml.
- Зашифрованные письма (S/MIME) пока показываются плашкой: расшифровка в браузере будет
  на следующем этапе.
- Тёмная и светлая темы (по системе, выбор запоминается), адаптивная вёрстка, анимации
  (Motion), которые отключаются при настройке системы «уменьшить движение».
- Написать письмо, ответить, ответить всем, переслать (простой текст, до 50 получателей,
  поля «Копия» и «Скрытая»). Адрес отправителя выбирается из адресов самого ящика. Текст
  письма живёт только в памяти страницы, пока окно открыто; закрытие с несохранённым
  текстом спрашивает подтверждение. Отправленное письмо попадает в «Отправленные».
- Вложения при отправке, как в Gmail: кнопка «Прикрепить», перетаскивание файлов в окно письма,
  вставка из буфера обмена, полоска загрузки у каждого файла, счётчик «столько из 25 МБ», удаление
  файла крестиком. При пересылке вложения исходного письма уже в списке и заново не загружаются.
  Программы (.exe, .bat, .js и подобные) отправлять нельзя.

## Как письмо показывается безопасно

1. Сервер отдаёт текст письма как есть, ничего не вставляя в страницу.
2. Браузер очищает HTML (DOMPurify): убирает скрипты, формы, внешние стили, встроенные
   объекты, карты ссылок, обработчики событий. Встроенные стили вырезаются заранее: политика
   страницы всё равно их запретила бы.
3. Все ссылки внутри письма делаются неактивными. Настоящие адреса показываются списком под
   письмом с отметкой, если текст ссылки выглядит как адрес другого сайта, или в адресе
   необычные символы. Открытие только по кнопке, в новой вкладке, без передачи источника.
4. Картинки не из самого письма (data:) не загружаются: заменяются пометкой.
5. Результат кладётся в iframe с пустым sandbox (без скриптов, без форм, без переходов, без
   доступа к странице) и с политикой страницы, которая запрещает любые загрузки.
6. Вложения отдаются с типом octet-stream, Content-Disposition: attachment, nosniff и
   политикой sandbox, поэтому браузер ничего не открывает и не выполняет.

## Сервер

Маршруты (все, кроме входа, требуют сессии; запросы, меняющие данные, ещё и защиту от
подделки: свой заголовок, проверка Origin и Sec-Fetch-Site):

- POST /api/auth/login, POST /api/auth/logout, GET /api/auth/me
- GET /api/mailboxes, GET /api/identities
- GET /api/emails?mailbox=...&position=...&limit=...&q=...
- GET /api/emails/:id
- POST /api/emails/:id/seen, POST /api/emails/:id/trash
- POST /api/send
- GET /api/emails/:id/raw, GET /api/emails/:id/attachments/:blobId
- GET /health

Сервер не является открытым прокси: к Stalwart уходят только методы Mailbox/get, Email/query,
Email/get, Email/set, Identity/get и EmailSubmission/set, причём Email/set только с жёстко
заданными правками (флаг прочитано, перенос в корзину, удаление, создание и перенос своего
письма при отправке), а Identity/get только читает. Идентификаторы проверяются по строгому шаблону, вложение
отдаётся только если оно действительно принадлежит этому письму.

Настройки (переменные окружения):

- STALWART_URL: внутренний адрес Stalwart
- HOST и PORT: адрес и порт (по умолчанию 127.0.0.1:3000)
- ALLOWED_DOMAIN: домен ящиков, с другими войти нельзя
- ALLOWED_ORIGIN: адрес сайта для проверки Origin
- COOKIE_SECURE: true по умолчанию (cookie с префиксом __Host-)
- WEB_ROOT: папка собранного сайта (в образе задана)

Сессии: простой 30 минут, в сумме 12 часов, не больше 8 на ящик, до 300 запросов в минуту
на сессию. Перезапуск сервера закрывает все сессии.

## Как письмо отправляется

Браузер присылает получателей, тему, текст и (для ответа) номер исходного письма. Всё
остальное решает сервер:

1. Проверяет входные данные до обращения к Stalwart: адреса по строгому шаблону (без пробелов,
   скобок, кавычек, переводов строк), не больше 50 получателей, тема до 300 знаков и в одну
   строку, текст до 100 000 знаков. Тело запроса отправки до 256 КБ, у остальных маршрутов 16 КБ.
2. Берёт адрес отправителя из списка адресов ящика на самом Stalwart. Браузер выбирает только
   номер из этого списка, подставить чужой адрес «От» нельзя.
3. Для ответа сам читает у исходного письма идентификатор и цепочку ответов (In-Reply-To и
   References), чтобы письмо встало в ту же переписку.
4. Создаёт письмо в «Черновиках», отправляет, затем переносит копию в «Отправленные». Получатели
   передаются явно, поэтому скрытая копия точно доходит и не показывается остальным.
5. Если отправка отклонена, черновик удаляется, а пользователь получает понятное объяснение
   (например, «сервер не разрешает отправлять с этого адреса»). Если письмо ушло, а копию
   перенести не удалось, сообщается об этом отдельно.
6. Не больше 40 писем в час с одного ящика (защита на случай чужого доступа к сессии).

## Вложения при отправке

Файл загружается сразу после выбора, отдельным запросом, чтобы отправка письма потом была
быстрой. Браузер присылает содержимое как есть (без разбора формы), показывает ход загрузки.
Сервер, не читая тело, сперва проверяет всё, что можно проверить по заголовкам:

1. Подлинность запроса (свой заголовок, Origin, Sec-Fetch-Site), наличие сессии, размер файла
   по заголовку Content-Length (без него отказ 411, больше предела отказ 413).
2. Не больше трёх одновременных загрузок и 100 загрузок в час с сессии, иначе ответ 429.
   Файл держится в памяти целиком, поэтому число одновременных загрузок ограничено.
3. Затем проверяет имя и тип. Имя очищается от путей и управляющих знаков. Запрещены исполняемые
   типы по расширению (список Gmail плюс sh) и по началу содержимого (Windows PE, Linux ELF,
   macOS Mach-O, Java class): переименованная программа тоже отклоняется.
4. Передаёт файл в Stalwart и записывает его идентификатор в список файлов этой сессии.

Пределы: 25 МБ на один файл и 25 МБ на все вложения письма вместе, не больше 20 файлов. Если
Stalwart объявляет меньшие пределы, действуют они (сервер читает их из сессии JMAP и помнит 10
минут). Страница повторяет те же проверки для удобства, главная проверка на сервере.

При отправке письма сервер принимает только идентификаторы файлов из списка своей сессии:
чужой или выдуманный идентификатор отклоняется. При пересылке сервер сам читает вложения
исходного письма у Stalwart и прикладывает их заново, браузеру достаточно указать, что их
нужно сохранить. После успешной отправки файлы убираются из списка сессии; закрытие окна
письма убирает неотправленные файлы из этого списка (загруженное на почтовом сервере удаляет
сам Stalwart по сроку хранения загрузок).

Шлюз перед сервером должен пропускать тело запроса до 26 МБ на адресе /api/attachments и ждать
дольше обычного; остальные адреса остаются с малым пределом.

## Сборка, тесты, образ

    npm test --workspace @dvmail/server
    npm test --workspace @dvmail/web
    npm run build --workspace @dvmail/web
    docker build -f apps/server/Dockerfile -t dvmail-web .

Тесты сервера идут на заглушке Stalwart с форматами ответов, снятыми с настоящего Stalwart
0.16 (на ящике без письменных данных проверена структура ответов: сессия, папки, список,
письмо с вложением, скачивание, личность отправителя). Интерфейс проверен в настоящем
браузере (Chromium) с боевой политикой страницы: вход, чтение, темы, телефон и планшет, набор
из 41 атаки через HTML письма (скрипты, обработчики, формы, стили, маячки, карты ссылок и
другие). Образ собирается в несколько ступеней, скрипты установки пакетов отключены, в
итоговый образ не попадают инструменты сборки, процесс идёт без root.

## Известные ограничения

- Стили из писем не применяются (строгая политика страницы): письма выглядят проще
  оригинала. Цвета из атрибутов HTML (bgcolor, color) сохраняются.
- Внешние картинки не загружаются совсем, включить их для одного письма пока нельзя.
- Зашифрованные письма пока не расшифровываются.
- Отправка только простым текстом, без оформления. Черновики на сервере не сохраняются (пока
  окно открыто, текст и файлы в памяти страницы и в списке сессии).
- Отправка и вложения проверены тестами на заглушке по стандарту RFC 8621 и в браузере; на
  настоящем Stalwart их нужно проверить отдельно (письмо с файлом с тестового ящика, пересылка
  письма с вложением).
- Вложения проверяются по имени и началу содержимого, антивирусом клиент не является: файлы
  внутри архивов не просматриваются. Остальное делает фильтр самого Stalwart и получатель.
- Файл при загрузке держится в памяти сервера целиком (до 25 МБ, три одновременно на сессию).
