План аудита безопасности DVMail
===============================

Цель: максимальный аудит всего проекта, включая то, что не лежит на поверхности и что станет
проблемой позже (перспектива). Автор кода плохо находит свои ошибки, поэтому слоёв несколько:
автоматические сканеры, ручной разбор по чек-листу, живые проверки на тестовой копии, второе мнение.

Правило: активные проверки на боевых серверах только по явному "да" владельца и ничего не ломая.
Туннели, VPN, сайты и почта неприкосновенны.

Слои проверки
-------------

1. Код приложения (сервер входа, админка, страница, расшифровка)
   - Модель угроз (threat model): кто и как атакует каждую часть. Документ ведётся по ходу работы.
   - Вход и сессии, защита от подделки запросов (CSRF), XSS и политика безопасности страницы (CSP).
   - Утечки в ошибках и логах, перегрузка (DoS), тайминговые атаки, лимиты размеров.
   - Недоверенный ввод: сами письма. Разбор ASN.1 при расшифровке проверить "зашумлением" (fuzzing).
   - Показ HTML-писем: изолированная рамка (sandbox), очистка (DOMPurify), картинки-маячки.

2. Цепочка поставок (supply chain)
   - Зависимости и их скрипты установки, закреплённые версии, лицензии, npm audit.
   - Сборка на GitHub с минимальными правами, действия по хешу коммита, подпись образов, SBOM.
   - Без ботов в репозитории: обновления проверяет собственный скрипт по расписанию.

3. Криптография и перспектива
   - Где хранится ключ расшифровки в браузере (неизвлекаемый ключ в IndexedDB), копия и восстановление.
   - Риски "сейфа администратора". Темы и адреса писем не шифруются. Нет защиты старой переписки
     от будущей кражи ключа (forward secrecy).
   - Горизонт: замена RSA гибридной схемой, устойчивой к квантовым компьютерам (ML-KEM).
     В формат закладываем возможность смены алгоритма заранее.

4. Инфраструктура
   - Открытые порты снаружи, Docker в обход UFW, ключи и права туннелей (ограничить пробросы).
   - Stalwart: версия, переход на 1.0, лимиты, автобан. Сертификаты. Резервные копии и проверка восстановления.
   - DNS-защита почты: SPF, DKIM, DMARC (позже reject), MTA-STS, TLS-RPT, DANE. PTR. Репутация IP.
   - Физическая безопасность мини-ПК, питание, диски.

5. Процессы
   - Секреты в истории git (сканировать всю историю). Настройки GitHub: двухфакторка, защита веток, права Actions.
   - Ротация ключей. Журналы и оповещения. План действий при взломе. Запасной путь при потере доступа.

Порядок
-------

1. Сейчас, по ходу работы: вести модель угроз и список принятых рисков.
2. Перед первым реальным использованием webmail: автоматические проверки (сканеры уязвимостей,
   поиск секретов, анализ кода) и ручной разбор по чек-листу.
3. Живые проверки только на тестовой копии, затем зашумление парсера и нагрузка.
4. Второе мнение: отчёты независимых аудиторов (свои агенты владельца), исправления делаются
   скриптами, каждое с проверкой до применения.
5. Итог: отчёт по степени опасности и план исправлений.
